Overview

This project is a small local web app built with Streamlit. You upload or paste Markdown (for example your repository README.md), adjust print settings, and download a PDF styled for reading and printing.

Processing happens on your computer; nothing is uploaded to a third-party conversion service by the app itself.

Requirements

  • Python 3.10 or newer (3.11 is a good default).
  • pip for installing dependencies.
  • A terminal and a modern web browser.

Install and run

  1. Clone the repository (replace the URL with yours if you forked it).
git clone https://github.com/YOUR_USERNAME/md-readme-to-pdf.git
cd md-readme-to-pdf
  1. Create and activate a virtual environment.
python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
  1. Install dependencies and start the app.
pip install -r requirements.txt
streamlit run app.py

Streamlit prints a local URL—usually http://localhost:8501. Open it in your browser.

Tip: Keep the terminal session open while you use the app. Press Ctrl+C in the terminal to stop the server when you are done.

Using the app

  1. Add Markdown. Either use Upload a Markdown file and choose .md, .markdown, or .txt, or paste content into Or paste Markdown here.
  2. Set layout in the sidebar (see Page size and margins).
  3. Click Generate PDF. Wait until the success message appears.
  4. Click Download PDF. The suggested filename matches your uploaded file (for example README.pdf for README.md) or defaults to README.pdf when you only pasted text.

If you see a warning about layout warnings, open the PDF anyway and check complex sections (large tables or unusual HTML). The PDF engine may still produce a usable file.

Page size and margins

These options are in the sidebar under Print layout.

Option Choices Notes
Page size A4, Letter Pick what your printer or region expects.
Margins Comfortable, Tight, Wide Comfortable is the default balance; Tight fits more on a page; Wide gives more whitespace.

What Markdown features work

The app uses Python-Markdown with common extensions. Typical project README content works well, including:

  • Headings, paragraphs, bold, italic, links
  • Ordered and unordered lists
  • Fenced code blocks and inline code
  • Tables
  • Blockquotes
  • Horizontal rules

Very advanced Markdown or mixed raw HTML may render differently in the PDF than on GitHub; preview the PDF before sharing.

Images and badges

  • Images from URLs (shields.io badges, CDN diagrams) appear in the PDF only if the PDF library can download them. Corporate proxies, firewalls, or SSL inspection may block those requests—badges might be missing while text remains.
  • Relative paths such as ./docs/screenshot.png are not automatically resolved from your disk when you only upload the Markdown file. Use a full URL to the image if you need it embedded reliably.

Troubleshooting

Command not found: streamlit

Activate your virtual environment and run pip install -r requirements.txt again. Use the same Python you used for the venv (for example python3 -m pip install -r requirements.txt).

Port already in use

Another app may be using port 8501. Stop the other process, or run Streamlit on another port:

streamlit run app.py --server.port 8502

PDF looks different from GitHub’s preview

GitHub’s Markdown renderer is not identical to this pipeline (Markdown → HTML → PDF). Small differences in spacing, fonts, or tables are normal.

Publish this doc on GitHub Pages

This folder contains static files for a simple documentation site. No build step is required.

  1. Push the docs/ folder to your GitHub repository.
  2. In the repo on GitHub, open Settings → Pages.
  3. Under Build and deployment, set Source to Deploy from a branch.
  4. Choose branch main (or your default branch) and folder /docs, then save.

After a short build, your usage guide will be available at: 

https://YOUR_USERNAME.github.io/REPO_NAME/

Replace YOUR_USERNAME and REPO_NAME with your GitHub username and repository name. The entry page is docs/index.html, which GitHub Pages serves as the site root.

Organization policy: If your employer restricts public GitHub Pages or external hosting, follow internal guidance before enabling Pages.
